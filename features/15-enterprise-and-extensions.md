# 企业能力与按需扩展

- 优先级：P2 / 按需
- 当前基础：待实现，不作为默认 MVP 前置
- 文档状态：设计草案，尚未按本文实现与验收
- 依赖：01—14 按所选能力依赖。

## 需求

- 企业能力可包括 SSO、MFA、成员自动同步、自定义角色、域名验证与专属资源。
- 增长能力可包括优惠码、推荐奖励、帮助中心、工单及产品分析。
- 仅在具体客户或产品需要时展开，避免把所有可能功能作为基础版本范围。

## 设计

| 能力 | 最小需求与设计 | 实现切入点与验收 |
| --- | --- | --- |
| SSO | `IdentityProvider` 归组织，`ExternalIdentity` 以 issuer + subject 唯一；不可仅按同邮箱自动合并账号 | 配置回调验证与登录策略；验证错误租户、重放、证书轮换及受控应急登录 |
| MFA | 加密保存认证秘密，恢复码存摘要，敏感动作要求近期二次验证 | 先为平台管理员接入；验证恢复码单次使用、失窃设备重置和审计 |
| 成员同步 | 将外部目录身份映射到组织成员，禁用要及时撤销权限 | 接入同步凭据、事件幂等和定期核对；验证重复事件与离职失权 |
| 自定义角色 | Role、Permission 和成员角色关联，禁止授予超出操作者能力的权限 | 从固定角色矩阵演进；验证权限继承、缓存失效和自我提权拒绝 |
| 自定义域名 | 域名唯一、先验证所有权再绑定，记录证书和验证状态 | 验证租户路由、证书续期、解除绑定和悬空域名回收 |
| 优惠与推荐 | 优惠有范围、期限、次数和不可叠加规则，奖励有防重复标识 | 接入渠道优惠与退款冲正；验证并发核销及退单回收 |
| 支持工单 | Ticket 归组织和提交者，支持人员访问受角色约束 | 创建、回复、状态流转和通知；验证附件权限及跨租户隔离 |
| 产品分析 | 定义最少事件及用途，将访问统计与计费账本分开 | 异步采集和聚合；验证权限、删除流程与数据最小化 |

## 实现步骤

1. 选择一个有明确需求的能力，复制 [模块模板](TEMPLATE.md) 建立独立需求文档。
2. 补齐数据模型、协议边界、流程、迁移和失败处理；涉及外部协议时在实施时核对官方文档。
3. 确定受影响角色、套餐及运维责任，再排入路线图。
4. 不直接以本概览中的简表作为完整企业能力实现规格。

## 验收标准

- [ ] 所选能力有独立规格和可测试验收条件。
- [ ] 不破坏既有租户隔离、角色权限、计费及账号恢复机制。
- [ ] 客户使用与平台运维两条流程均已覆盖。
