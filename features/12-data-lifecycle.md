# 数据导入导出、删除与保留

- 优先级：P1；删除保护为 P0
- 当前基础：待实现
- 文档状态：设计草案，尚未按本文实现与验收
- 依赖：02、03、07、08、10。

## 需求

- 授权用户可导入/导出业务数据，查看进度、失败原因和结果。
- 用户注销与组织删除分开处理；删除提供确认、冷静期和完成通知。
- 明确各类数据保留、备份过期及恢复边界；具体期限由产品和适用要求另行确定。

## 设计

- `DataTransfer(organization_id, requested_by_id, kind, status, processed_count, failed_count, expires_at)`；大文件异步处理，结果私有且短期有效。
- 导入先校验并预览，再分批提交；定义行级错误报告和导入业务唯一键。CSV 导出防电子表格公式注入。
- `DeletionRequest(subject_type, subject_id, requested_by_id, status, scheduled_at, completed_at)`；requested → scheduled → processing → completed，开始执行前可 canceled，失败保留检查点可恢复。
- 用户注销前转移其仍担任唯一 owner 的组织；组织删除先处理续费和集成凭据，再冻结写入、进入清理任务。
- 备份中的删除记录通过删除台账在恢复后重新执行；保留要求中的账单/审计数据单独控制访问，不无限期保留全部用户资料。
- `POST/GET .../exports`、`POST/GET .../imports`、`POST/DELETE .../deletion_request`、`POST /api/v1/user/deletion_request`。

## 实现步骤

1. 列出数据分类、保留周期、删除顺序和不可撤回的阶段，形成执行清单。
2. 实现导入预检、分批任务、权限复核和私有导出下载。
3. 实现删除编排、取消续费、撤销凭据和附件清理，所有步骤幂等且可续跑。
4. 做备份恢复演练，恢复后应用删除台账；大批量任务设置资源上限。

## 验收标准

- [ ] 导出执行及下载时再次检查权限，其他租户不可读取结果。
- [ ] 导入重复提交不重复记录，坏行有错误原因且不污染其他行。
- [ ] 删除中断可恢复，冷静期取消有效，删除后不再扣款或开放凭据。
- [ ] 备份恢复不会重新开放已删除账号和数据。
