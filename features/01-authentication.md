# 账号与认证

- 优先级：P0
- 当前基础：已有基础，需完善
- 文档状态：设计草案，尚未按本文实现与验收
- 依赖：无；租户创建流程依赖 02。

## 需求

- 用户可注册、登录、退出、找回密码、验证邮箱和修改密码；响应避免暴露邮箱是否存在。
- 用户可查看并撤销自己的登录设备；改密、封禁后旧凭证失效。
- 浏览器会话与 API Token 都必须有过期和退出语义；MFA、社交登录作为后续扩展。

## 设计

- 复用 `User`、Devise、devise-jwt；当前未启用 `confirmable`，JWT 使用 Null 撤销策略，不能视作已完成验证与撤销。
- 增加确认邮箱所需字段；拟新增 `AuthSession(user_id, jti_digest, expires_at, revoked_at, last_used_at)`，以会话白名单落实逐设备撤销；只存 Token 标识摘要。
- 用户增加 `status` 和 `credentials_version`；校验 JWT 时同时校验会话、用户状态和凭证版本，改密时递增版本并撤销会话。
- 邮箱变更需验证新邮箱，验证前保留原邮箱；验证、重置链接单次使用并设置有效期。
- 保留 `/users`、`/users/sign_in`、`/users/sign_out`、`/users/password`；拟新增 `GET /api/v1/auth_sessions`、`DELETE /api/v1/auth_sessions/:id`。
- Cookie 认证保留 CSRF 防护；JSON API 明确仅使用 Bearer 认证；密码、完整 Token 不进入日志。

## 实现步骤

1. 补充邮箱确认迁移和邮件页面，明确存量用户确认策略，不默认把未知邮箱标为已验证。
2. 增加 JWT 会话登记及校验服务，替换 Null 策略；检查 HTML 与 JSON 的登录退出路径。
3. 在改密、封禁流程撤销凭证；通过 14 的限流策略保护登录、重置与确认接口。
4. 邮件提交后经 GoodJob 发送；补充认证请求测试及接口文档。

## 验收标准

- [ ] 正确凭据可登录；过期、撤销、被封禁用户的 JWT 均被拒绝。
- [ ] 退出设备 A 后 A 失效，设备 B 按产品策略保持有效；改密后所有旧会话失效。
- [ ] 验证与重置链接不可重放；重置请求不泄露邮箱是否注册。
- [ ] 浏览器与 API 两种认证路径分别通过测试。
