# 功能开关与发布配置

- 优先级：P1
- 当前基础：已有 Flipper、配置文件、任务和管理入口
- 文档状态：设计草案，尚未按本文实现与验收
- 依赖：02、03、10。

## 需求

- 新功能可按环境、组织或比例灰度开放，异常时快速关闭。
- 运营可查看功能状态和变更记录；开关有负责人、目的和清理时间。
- 发布开关与套餐权限各自维护。

## 设计

- 复用 Flipper 及 `config/feature-flags.yml`，现有使用约定见 [功能开关文档](../docs/feature_flags.md)。
- 新增组织 actor 标识，例如 `Organization;123`；需要组织一致体验的功能使用组织作为分组单位。
- 开关登记 name、owner、default、expires_at、failure_behavior；涉及权限和敏感数据的开关故障时默认拒绝。
- 管理入口沿用 `/admin/feature-flags`，仅开放给授权平台角色；记录变更前后状态和原因。
- 关闭功能前定义在途任务、已有数据和外部副作用的处理，不把开关当数据库回滚工具。

## 实现步骤

1. 补充组织 actor 与统一功能检查入口，叠加角色和套餐权益校验。
2. 增加变更审计、权限和组织灰度流程；环境配置禁止互相覆盖。
3. 功能稳定后移除过期开关及分支，保留必要的紧急关闭开关。

## 验收标准

- [ ] 同一组织成员体验一致，另一个组织不受影响。
- [ ] 开关开启也不能绕过角色或付费权益。
- [ ] 紧急关闭、缓存失效、故障默认值和在途任务处理已验证。

## 实施前确认

- 按 [统一架构约定](00-architecture.md) 核对数据归属、权限、幂等及兼容性。
- 将涉及的产品参数、供应商选择和历史数据处理写入本模块的决策记录；本文默认值可以修改，但需同步依赖模块。
- 开工后补充实际变更文件、迁移结果、测试证据及上线/回滚记录；完成验收后才将状态改为已实现。
