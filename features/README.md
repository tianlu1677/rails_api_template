# SaaS 基础功能设计目录

这里保存可逐项实施的 SaaS 功能需求、设计、实现步骤和验收标准。本文档基于当前 Rails API Template 源码梳理，默认面向多租户 SaaS；单人产品可采用单成员组织，免费产品可暂缓支付模块。

**本目录是规划，不代表功能已完成。** 所有模块当前均为设计草案；“已有基础”表示存在相应代码或依赖，不表示已在生产环境验证。基线检查日期：2026-09-21。

## 如何使用

1. 先读 [统一架构约定](00-architecture.md)，再选择下表中的一个模块。
2. 按“需求 → 设计 → 实现步骤 → 验收标准”推进；先完成依赖，不一次性生成全部模块。
3. 开始实现前确认该模块的产品参数及历史数据策略，把决策写回文档。
4. 实现后补充实际文件、迁移、测试、上线和回滚记录；验收通过后更新状态。
5. 新功能复制 [模块模板](TEMPLATE.md)，维持同一结构。

## 当前项目基线

以源码为准，根 README 中的能力描述不能替代验证：

- [Gemfile](../Gemfile)：Rails、PostgreSQL、Devise/JWT、ActiveAdmin、GoodJob、Flipper、Active Storage 相关依赖、分页搜索、文档及监控工具。
- [User](../app/models/user.rb)：具备注册、密码认证和找回密码基础；未启用 confirmable，JWT 使用 Null 撤销策略；社交账号方法存在不等于完整社交登录已接入。
- [路由](../config/routes.rb)：已有用户认证、资料、Posts、设置、健康检查及管理入口；本目录新增 API 均为拟议接口。
- [数据库结构](../db/schema.rb)：已有 users、admin_users、posts、settings、Active Storage、Flipper 和 GoodJob 相关表；尚无组织、成员、套餐、订阅、用量及审计业务表。实施前还需核对迁移和目标环境。
- [PostsController](../app/controllers/api/v1/posts_controller.rb)：当前全局查询 Post，不具备租户隔离，不能直接复用为生产多租户查询。
- [Setting](../app/models/setting.rb)：全局键值配置，后续组织设置需独立作用域。

## 建议实施顺序

1. **安全与租户底座**：01 认证、02 组织、03 权限、04 设置；同步接入 10 关键审计及 14 运行保障。
2. **最小可用产品**：实现自身核心业务并接入租户与权限；07 事务邮件、11 首次使用；涉及文件则做 08，开放 API 产品则提前做 09。
3. **收费闭环**：先做 06 静态套餐和配额，再做 05 支付订阅，最后打通权益更新、通知与对账。05 与 06 的业务关联不要求同时从零实现。
4. **自助与运营完善**：07 站内通知、10 审计查询、12 导入导出与完整删除、13 灰度发布。
5. **按需扩展**：09 对外集成及 15 企业能力。

MVP 不包含所有清单项，但不能跳过所选功能需要的授权、隔离、幂等和失败恢复。数据库备份和恢复演练属于上线准备。具体业务（例如项目管理、CRM、内容生产）需另建 feature 文档，本目录仅覆盖公共 SaaS 能力。

## 完成定义

- 需求与边界明确，权限及失败路径有实现。
- 数据库约束、存量数据迁移和回滚/补偿方案可执行。
- 对应 RSpec 请求、服务或任务测试通过；涉及租户时包含跨租户拒绝测试。
- API 文档、管理入口、监控及运行说明同步。
- 在相应环境按验收清单核验，并记录证据；不能仅因合并代码标记完成。
