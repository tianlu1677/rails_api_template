# 组织与多租户

- 优先级：P0
- 当前基础：待实现
- 文档状态：设计草案，尚未按本文实现与验收
- 依赖：01；上线前必须接入 03。

## 需求

- 用户可创建、加入、切换多个组织；个人产品也可使用单成员组织。
- 组织之间的数据、附件、任务、缓存和统计互相隔离。
- 组织可修改名称、暂停、申请删除；删除需处理订阅及数据保留。

## 设计

- 采用共享 PostgreSQL 数据库、共享表、显式 `organization_id` 的初始方案。
- 拟新增 `Organization(name, slug, status, timezone, locale)` 与 `Membership(organization_id, user_id, role, status)`；成员关系在 03 细化。
- 租户资源统一为 `/api/v1/organizations/:organization_id/...`；组织列表只能从当前用户有效成员关系查询。
- 通过 `Current.organization` 表达请求上下文，但查询必须从已授权组织关联出发，不能只依赖 default_scope；请求结束清理上下文。
- 租户外键非空并建索引；租户内唯一项使用联合唯一索引。跨业务表关联应验证同租户，关键关联采用复合约束。
- 缓存键包含租户；Job 显式携带组织 ID 并重建上下文；跨租户 ID 返回 404。
- `Post` 当前列表使用 `Post.all`、详情使用 `Post.find`，尚无租户隔离，迁移时必须修改。

## 实现步骤

1. 创建组织与成员表及关联；组织和首位 owner 在同一事务创建。
2. 增加租户上下文加载和基础控制器校验，再接入业务资源与后台任务。
3. 为存量资源先加可空租户字段，按经确认的归属规则回填，校验无孤儿后加非空和外键；不可将全部历史数据盲目归同一租户。
4. 切换查询与写入路径；组织暂停时拒绝业务写入，保留账单、导出和恢复入口。
5. 组织删除接入 12；后续有隔离要求时再评估数据库级行安全或独立库。

## 验收标准

- [ ] 用户 A 无法通过列表、ID、搜索、附件、导出、Job 访问组织 B 数据。
- [ ] 切换组织不复用旧组织缓存和权限结果。
- [ ] 无租户上下文的业务请求拒绝执行；任务串行复用线程也不会串租户。
- [ ] 存量数据回填有数量核对、异常清单和回滚方案。
